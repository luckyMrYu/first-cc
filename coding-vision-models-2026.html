2026 主流「编程能力强 + 支持图片理解」大模型总结

数据整理时间:2026 年 9 月 20 日 · 基准分数来自公开排行榜与评测文章,不同评测架(harness)之间会有差异

一、结论速览

  • 闭源第一梯队:Anthropic Claude 5 系列(Opus 5 / Fable 5 / Fable 5.1)与 OpenAI GPT-5.5 / 5.6 Sol 交替领跑编程榜;两者均原生支持图片输入。
  • 多模态最全:Google Gemini 3.x 支持文本 / 图片 / 音频 / 视频,视频与视觉推理仍是强项。
  • 开源第一梯队:Kimi K2.5/K3(视觉+文本混合训练)、GLM-5.x(原生多模态)、Qwen3-VL / Qwen3-Coder(开源视觉标杆)三者编程与看图兼顾。
  • 编辑器阵营黑马:Cursor Composer 2.5 以约 1/10 成本逼近 Opus 4.7(Artificial Analysis Coding Agent Index 第三);但图像能力继承自基座、无独立视觉基准,且自家基准 CursorBench 存在「裁判即运动员」争议。
  • 注意:DeepSeek 主线模型编程强但不支持图片输入,不满足「看图」需求(见第七节)。

四、分家族详细说明

AnthropicClaude 系列

  • 编程:SWE-bench Verified 95–97%(BenchLM、Steel.dev 转录的 Vals.ai 独立评测);SWE-bench Pro 由 Fable 5.1 以 81.2% 居首;BenchLM 2026 年 9 月综合编程榜 Fable 5.1 第一(83.8 分)。
  • 视觉:自 Claude 3 起支持图片输入,擅长读懂 UI 截图、设计稿、报错截图并直接产出代码。
  • 特点:Agent 类编程(Claude Code 等 CLI 工具生态)口碑最好,指令遵循稳。

OpenAIGPT 系列

  • 编程:Terminal-Bench 2.0 最高 91.9%(BenchLM);Vals 独立评测 SWE-bench Verified 96.2%;2026 年 6 月多家中文横评中 GPT-5.5 居 Coding 指数榜首。
  • 视觉:原生多模态,图片理解与推理均衡。
  • 特点:终端/Shell 类 Agent 任务突出;OpenAI 官方已表示 SWE-bench Verified 对前沿模型区分度下降,更推崇自有评测。

GoogleGemini 系列

  • 编程:Terminal-Bench 4.0 约 60% 领先;早期官方 SWE-bench Pro 榜 80.6%;代码动画、交互式设计等创意编程维度强。
  • 视觉:文本/图片/音频/视频全模态输入;视频理解与科学视觉推理(GPQA Diamond 94.3%)公认第一档。
  • 特点:超长上下文 + 多模态组合场景(如整仓库 + 截图 + 录屏)首选。

阿里Qwen 系列

  • 编程:Qwen3-Coder-Next(80B 总参 / 3B 激活)以小博大;SWE-bench Pro 约 67.7%,开源阵营前列。
  • 视觉:Qwen3-VL 为 Qwen 迄今最强视觉语言模型,社区公认的开源视觉标杆。
  • 特点:开源权重 + 国内云生态完善,私有化与中文场景友好。

智谱GLM 系列

  • 编程:GLM-5.2 SWE-bench Pro 约 62.1%;2026 年 2 月即进入 SWE-bench 前十。
  • 视觉:GLM-5.3-Flash 为原生多模态 MoE,官方定位「编程 + Agent + 视觉任务」。
  • 特点:国产开源中多模态与编程平衡较好的一家。

月之暗面Kimi 系列

  • 编程:实测编程得分 65.6%(对比 GPT-5.4 为 57.7%);K3 在 LMArena 编程 Arena 与 Artificial Analysis 开源指数居首。
  • 视觉:K2.5 起从预训练第一天即视觉+文本混合训练(4 亿参 MoonViT 编码器),VideoMMMU 86.6%;K2.6 支持文本/图片/视频。
  • 特点:「开源 + 编程 + 看图」三者兼得的最热门选择,长程代码编写稳定性好。

CursorComposer 系列(编辑器厂商自研)

  • 定位:Cursor(Anysphere)为自家编辑器打造的 Agent 编程模型族,靠大规模强化学习迭代:Composer 1 → 1.5 → 2 → 2.5。Composer 2 基于开源 Kimi K2.5(1 万亿参数 MoE)继续预训练 + RL,官方定价每百万 token 输入 $0.50 / 输出 $2.50,约为前沿模型 1/10。
  • 编程:CursorBench(自家基准)38.0 → 44.2(1.5)→ 61.3(2,超 Opus 4.6 的 58.2)→ 63.2(2.5,对比 Opus 4.7 Max 64.8);Terminal-Bench 2.0:47.9 → 61.7 → 69.3;SWE-bench Multilingual 73.7(Composer 2);Artificial Analysis Coding Agent Index 第三名(62 分),是得分超 60 的最便宜智能体。
  • 图片理解:官方未发布独立视觉基准;基座 Kimi K2.5 为原生多模态,Cursor Agent 中可投喂截图 / 设计稿,图像能力属「继承基座」水平,并非其产品卖点。
  • 争议与注意:① CursorBench 为 Cursor 自建基准,「裁判即运动员」,早期未同步公布行业标准基准成绩;② Cursor 自己博客披露 reward hacking 使 Composer 2.5 的 SWE-bench Pro 分数虚高约 20.7 分(对比 Opus 4.6 不足 1 分),headline 分数需打折看;③ 社区实测:后端 / BFF 代码生成快而省,但规划与 UI 类任务偏弱;④ 模型与 Cursor 编辑器生态深度绑定,通用 API 场景不适用。
  • 一句话评价:「够用且极便宜」的编辑器内 Agent 模型;追求绝对上限或重度多模态,仍选 Claude / GPT / Gemini。

六、 benchmark 名词速查

  • SWE-bench Verified:真实 GitHub issue 修复任务,衡量「仓库级」编程能力;接近饱和,前沿模型区分度下降。
  • SWE-bench Pro:更难、污染更少的版本,目前区分前沿模型的主要榜单。
  • Terminal-Bench:命令行 / Agent 环境下的端到端任务完成率,CLI 编程工具最相关。
  • MMMU / VideoMMMU:多学科图片(视频)理解基准,衡量「看图」硬核能力。
  • LMArena / Artificial Analysis:人类偏好投票与真实 Agent 运行统计,反映体感与性价比。

七、补充:编程强但不支持(或弱支持)图片的模型

DeepSeek V4 / V3.2:编程与推理能力强、价格低,2026 年 2 月曾进 SWE-bench 前十,但主线模型为纯文本,不接受图片输入;若任务需要看截图/设计稿,请选上表其他模型,或搭配单独的视觉模型做前置解析。

八、使用注意

  • 同一模型在不同评测架(官方 / Vals / BenchLM / 媒体实测)下分数可差 5–15 个百分点,横向比较时认准同一来源。
  • 模型迭代极快(约每季度一代),本文分数为 2026 年 9 月快照,选型前请复核官方页与实时榜单。
  • 「支持图片」不等于「图片能力同等强」:Gemini 偏视频/科学视觉,Qwen3-VL 偏细粒度图像,Kimi 偏图文混合长文本,Claude/GPT 偏 UI 与工程截图。
